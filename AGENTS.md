# AGENTS.md — kiro-stopwatch

Project rules for agents working in this repository. Facts and decisions with dates live in
`_MEMORY.md` (read it with `mem context .`); user-facing setup and commands live in `README.md`;
architecture in `docs/design-docs/swlink-architecture.md`; open issues in `docs/unresolved.md`.
This file is the short list of things that will bite you if you skip them.

## Development loop

1. Build and run on the Mac first: `pio run -e native && ./.pio/build/native/program`
   (needs `export HOMEBREW_PREFIX=/opt/homebrew`). Iterate here until the screen is right.
2. Only then flash: `pio run -e stopwatch -t upload --upload-port /dev/cu.usbmodemXXXX`.
   Port name changes between plugs; find it with `ls /dev/cu.usbmodem*`.
3. Use hardware for what the host cannot model: brightness, audio, real IMU, power, Wi-Fi/BLE.

Every project keeps one `src/main.cpp` compiled by both `native` and `stopwatch` environments.
Never fork a second "simulator version" of the UI logic. Host-only glue (a `Serial` shim,
`using lgfx::millis`, the SDL `main`) goes behind `#if !defined(ARDUINO)` / `#if defined(SDL_h_)`.
Device-only peripherals need `#if defined(ESP_PLATFORM)`: `M5.Mic` in particular has no host
implementation and fails at link time, not compile time.

**Stop the swlink daemon before flashing.** It grabs the serial port the moment the device
re-enumerates, and esptool then fails with `Could not configure port: Device not configured`.

## Screen geometry — do not derive from `width()`

`M5.Display.width()` is 468 on the device (M5GFX 0.2.29: even-aligned buffer, `offset_x = 6`)
and 466 in the SDL simulator. Anything centred with `width()/2` is 1 px off on hardware and an
outline at `width()/2 - 2` leaves the visible circle bottom-right (seen on device 2026-09-14).

Use the physical constants instead, as `hello/src/main.cpp` does:

```cpp
static constexpr int kScreenDiameter = 466;
static constexpr int kCenterX = 233, kCenterY = 233;
static constexpr int kOutlineRadius = 230;   // stay a few px inside the glass edge
```

Touch coordinates are reported in the same 466 space; the touch controller maps 0..233 raw to
screen, so treat anything beyond radius ~233 from the centre as off-glass.

## Drawing on this AMOLED

- The panel is locked to 16-bit RGB565: `Panel_CO5300` hardcodes `0x3A = 0x55` and
  `_write_depth`. There is no 18/24-bit mode to switch to.
- Antialiasing pixels dimmer than roughly 24/255 read as **coloured specks**, because an emissive
  AMOLED lights the R/G/B subpixels of a dim grey pixel separately. Keep the ramp short and
  substantial — that is what `gen_kiro_body.py --floor` does.
- `fillEllipse`/`fillTriangle` are hard-edged. For anything the eye lands on use `drawWideLine`
  (antialiased) or the supersampled `fillEllipseAA` in `linkfw/src/face.cpp`.
- `linkfw/src/kiro_body.{c,h}` is generated by `linkfw/tools/gen_kiro_body.py`. Do not hand-edit;
  regenerate and note the size/flash cost.

## Serial and monitoring

- `M5.config().serial_baudrate` defaults to 0 and then `M5.begin()` never calls `Serial.begin()`.
  Set it to 115200 inside `#if defined(ARDUINO)`; the field does not exist on the host build.
- `Serial` is USB CDC on the USB-Serial/JTAG port. The host must assert DTR or output is
  discarded. `pio device monitor` does this but refuses to run without a TTY; from scripts use
  pyserial (`uv run --with pyserial`) with `dtr=True, rts=False`.
- RTS asserted while DTR is released resets the chip. Use it deliberately to capture boot logs;
  do not toggle the lines casually while reading.
- The ROM boot banner arriving with no `[app]` lines after it means the application is running
  but its serial was never initialised, not that it crashed.
- Match ports by USB VID/PID (`0x303A`/`0x1001`), not by globbing `/dev/cu.usbmodem*`: this Mac has
  other devices that enumerate the same way (an unrelated `LDR2001` cost an hour once).

## swlink specifics

- Protocol changes go to `docs/design-docs/swlink-architecture.md` first, then to both sides.
  `link/tests/` must stay green (`cd link && uv run pytest`).
- The firmware namespace is `swl`, not `link` — that name collides with POSIX `link()` on the host
  build.
- Button mappings execute **on the device** as BLE HID when a keyboard connection exists
  (`hello.hid` / `keys.hid`); the host's `pynput` injection is only a fallback and cannot reach
  input methods or HID-level consumers. Do not "fix" a key problem by improving synthetic events
  without first checking which path is active.
- macOS drops synthetic key events without Accessibility permission for the *responsible process*
  (the terminal that started the daemon), silently. `swlink/accessibility.py` probes it.
- Never write the user's Wi-Fi password to a host file or a log. `wifi.set` carries it over the
  live link into device NVS; the host only stores the pairing token.
- Editing the dashboard: `link/swlink/ui/index.html` is one file with inline JS; check it parses
  (`node -e "new Function(...)"`) since there is no build step. `face.js` mirrors the firmware
  animation for the preview — change both or the preview lies.
- Headless screenshots of the dashboard need a few seconds of virtual time: the mood/trigger/key
  pickers only populate after the first `_status` message arrives.

## Flashing safety

- Factory firmware has not been backed up. `scripts/backup-factory.sh` exists (chunked,
  `--no-stub`) but has not completed a full run; the user accepted restoring via M5Burner instead.
- Never write to flash outside `pio run -t upload` without stating what will be overwritten.
- On some v1.0 units the rear pin printed `BAT` is actually 5V IN. Do not suggest wiring a
  battery there.

## Libraries

- `lib_extra_dirs = ../references/projects` points both environments at the local clones so the
  simulator and the device compile the same library revision. Do not add `lib_deps` URLs.
- `references/projects/M5GFX` carries `patches/M5GFX-sdl-stopwatch-466.patch` (466x466 SDL
  window for `board_M5StopWatch`). Re-apply it after refreshing that clone.
- M5Unified requires M5GFX >= 0.2.29. The official UserDemo pins 0.2.19 and the ochyai
  simulator pins 0.2.27; behaviour such as the 468-vs-466 report differs across these.
- ArduinoJson comes from the UserDemo component checkout under `references/`.

## Layout

- `linkfw/` + `link/` — swlink: device firmware and host package (daemon, CLI, dashboard).
  File-by-file map in `docs/design-docs/swlink-architecture.md`.
- `hello/` — verified Hello World, the template for new projects (two envs, one source).
- `buddy/` — the original Kiro ghost mood display, driven by buttons or USB JSON lines.
- `sim-smoke/` — minimal SDL smoke test; keep it building when touching the M5GFX patch.
- `references/` — official PDFs and shallow clones; read-only except for the recorded patch.
- `scripts/` — device utilities. `backup/` is created on demand and is not committed.
- `docs/` — `requirements/` (what), `design-docs/` (how), `unresolved.md` (what is still open),
  `recommended-config.md` (the suggested default mapping and how to wire voice hotkeys).
